## 真机首跑：触摸完全无反应 → touch.c 手势状态丢失 bug（已修复）

- 现象：开发板跑 ./frame，FB/music 正常，menu.jpg 缺失报错（用户没拷），但**怎么点都没反应**
- 排查：photo.c（真机验证过）触摸用 `/dev/input/event6`，与 main.c 一致 → 不是设备路径问题；`[FB]` 能打印说明 touch_open 成功
- **根因**：touch_read() 的 sx/sy/cx/cy/pressed 是局部变量。内核触摸事件分批发（按下包 ABS_X/ABS_Y/BTN_TOUCH=1 → 抬起包 .../BTN_TOUCH=0），第一次调用读到按下后事件读空就 return，状态全丢；第二次调用读到抬起时 pressed==0，被当"孤儿抬起"忽略 → 永远等不到一次完整手势
- photo.c 能用是因为 click() 单次调用内阻塞 read，读完整个手势才返回
- **修复**：手势状态改 static 跨调用保留；空闲时 poll(timeout_ms) 等新事件，手势进行中 poll(-1) 无限等到抬起（与 photo.c 语义一致）
- 教训：触摸事件包跨 read/poll 调用拆分时，状态必须静态保留；嵌入式触摸层别用"读完一批就 break"的写法

## 音频检测与防爆音（用户怕测试时声音太大）
- 板子音频方案确认：RK3568 I2S0（fe400000.i2s）→ **rk817-codec**（PMIC 集成音频），HP_OUT=耳机、SPK=喇叭；另有 hdmi-audio-codec / spdif-out
- music.c 加 `volume_safe()`：play_thread 里 fork aplay **之前**逐个尝试 `amixer -q set '<控件名>' 40%`（控件列表：HP Volume / Speaker Volume / SPK Volume / Headphone / Speaker / PCM / Master），存在即设，防刚接设备爆音
- 安全测试流程：`amixer scontrols` 查控件 → `amixer set 'HP Volume' 0%` 静音 → 插耳机 → aplay 播 → `cat /proc/asound/card0/pcm0p/sub0/status` 看 RUNNING 确认数据在流 → 逐步调大
- 无耳机检测法：ALSA status=RUNNING + aplay 不报错 = 软件通路 OK；万用表交流档测 HP_OUT 引脚播放时有 mV 级跳动

## aplay Device or resource busy 修复（3 处防御）
- 根因：① 残留 aplay 占着声卡（手动测试/上次异常退出没清）；② kill(SIGTERM) 异步，旧 aplay 未释放设备时新 aplay 已 fork → EBUSY
- 修复 1：`music_init()` 启动时 `system("killall aplay")` 清场
- 修复 2：`music_stop()` kill 后 `usleep(150000)` 等旧进程释放声卡
- 修复 3：`play_thread()` 循环 fork aplay，失败（busy）等 150ms 重试最多 5 次；自然放完（退出码 0）才 break
- 诊断命令：`ps aux | grep aplay`、`fuser -v /dev/snd/pcmC0D0p`
- RK817 控件确认：Master（主音量）/ Playback Path（路由 HP/SPK/HP_SPK）/ Capture MIC Path；volume_safe() 命中 Master

## 「音乐没声音」根因：Playback Path = OFF（2026-08-20 上午）
- 用户上板：音乐列表正常显示 PLAYING，但耳机/喇叭完全没声
- 诊断 4 连：ps 无 aplay、ALSA closed、Master 100%（音量正常）、**Playback Path=OFF（根因）**
- 原因：volume_safe() 只压音量（Master），从不设路由；RK817 的 Playback Path 默认 OFF=codec 静音，aplay 数据照送但被吞
- 修复：volume_safe() 第一步先 `amixer set 'Playback Path' SPK_HP`（耳机+喇叭都出，没插耳机也能听到），失败退回 HP；音量从 40% 降到 20% 更防爆音
- 教训：RK817 这类 codec 有输出路由控件（Playback Path/Output Route），「音量对≠有声」，路由 OFF 照样没声音。排查顺序：进程→ALSA状态→音量→路由

## 路由 set 失败 + busy 双问题（2026-08-20 上午 2）
- 上板日志：只有 `[music] volume: Master -> 20%`，**无 path 打印** → Playback Path set 失败；aplay 5 次 busy

## 没声音排查（2026-08-20 上午 3）：文件/播放全通 + 两大发现
- aplay -v 铁证：文件标准 48kHz/16bit/stereo，播放正常（Ctrl+C 的 write error 是正常打断），数据到 'rockchip,rk809-codec'（注：components 里叫 rk817-codec，同系列 PMIC+codec 一体，软件同名）
