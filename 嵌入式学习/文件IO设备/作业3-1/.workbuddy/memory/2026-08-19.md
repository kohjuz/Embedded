# 2026-08-19 工作记录

## 1. 修复 libjpeg.a 链接错误
- 现象：`make` 编 .so 时报 `R_AARCH64_ADR_PREL_PG_HI21` 重定位错误，指向 `stderr`。
- 根因：`jpeg-9d/lib/` 中缺少开发链接 `libjpeg.so`，链接器 `-ljpeg` 找不到 .so 后退回非 PIC 的 `libjpeg.a`，导致无法链接进共享库。
- 处理：在 `jpeg-9d/lib/` 创建 `libjpeg.so` 指向 `libjpeg.so.9.4.0`，使链接器命中共享库。

## 2. 修复板子上运行找不到动态库
- 现象：板子运行 `./main` 报 `libLCD.so: cannot open shared object file`。
- 根因：动态链接器默认不搜索当前目录；且 `main`/`libjpg.so`/`libbmp.so` 还依赖 `libjpeg.so.9`，板子上没有。
- 处理：把 `.so` 挪到 `main` 同目录，并 `export LD_LIBRARY_PATH=.`，同时把 PC 侧的 `libjpeg.so.9.4.0` 拷到板子命名为 `libjpeg.so.9`。

## 3. 添加 PNG 图片显示支持
- 新增 `include/stb_image.h`：单头文件 PNG/BMP/JPG 解码库，无外部依赖。
- 新增 `src/png.c`：使用 stb_image 解码 PNG 为 RGBA，按 LCD BGRA 顺序写入 fb。
- 修改 `main.c`：打开 `case PNG` 分支，dlopen `libpng.so`。
- 修改 `Makefile`：`install` 目标新增 `libpng.so` 编译，`clean` 目标新增删除 `libpng.so`。
- 优点：不需要板子上安装 libpng，所有解码逻辑静态编译进 `libpng.so`，部署时只需把 `libpng.so` 一起 scp 过去。

## 4. 三个格式统一加"等比缩放 + 居中"自动对齐
- 需求：大图不再只显示左上角小角，小图居中显示。
- 算法：`scale = min(屏宽/图宽, 屏高/图高)` 取小值不裁边 → `dst_w/h = 原尺寸*scale` → `off_x/y = (屏尺寸-dst)/2` 居中 → 最近邻采样 `sx = di*图宽/dst_w`。
- `src/jpg.c`：解码后缩放（RGB 顺序，写入 fb 时 R↔B 交换）。
- `src/png.c`：stb_image 解码后缩放（RGBA，写入 fb 时 R↔B 交换，补 `#include <math.h>`）。
- `src/bmp.c`：**改动最大**——原流式读取改为整幅读入内存（逐行 read + lseek 跳过 pad），注意 BMP 自下而上存储（第0行是最底行），显示行 dj 对应 bmp 行 `bmp_height-1-sy`。
- 教训：BMP 有自下而上存储特性，JPG/PNG 是自上而下，方向处理不一样。

## 5. 自动对齐优化 + 部署排查
- 优化：`scale` 加 `fmin(1.0, ...)` 上限——大图缩小、小图保持原大小只居中，避免最近邻放大糊掉。
- 排查经验：板子上改完代码 `make && scp` 后，新 `.so` 只到 `/root/swj/mylib/`，必须 `mv mylib/*.so .` 才会覆盖 `~/swj/` 里的旧库；用户遇到"改了没效果"先查库版本（`ls -l` 对比大小）。
- **新坑：`undefined symbol: fmin`** —— `fmin` 在 `libm`，编译 .so 时没链 `-lm` 链接器不报错（.so 允许悬空未定义符号），运行时才炸。修复：`LDFLAGS += -lm`，且 png 编译行也要带 $(LDFLAGS)。教训：用 math.h 函数的 .so 必须显式 `-lm`。
