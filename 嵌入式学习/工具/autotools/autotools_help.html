Autotools 帮助文档

一页速查：工具职责 · 完整流程 · configure.ac / Makefile.am 语法 · 排错对照 —— 实战案例为本机 liblife 项目

一、工具链全景图

记忆锚点：.ac/.am 是你写的菜谱 → autoreconf -i 变出厨具（configure + Makefile.in）→ ./configure 看厨房里有啥 → make 炒菜。

二、七个工具的职责

工具名字拆解作用
autoscanauto(自动) + scan(扫描)扫源码生成 configure.scan 初稿，改名后当 configure.ac 用
aclocalac(autoconf) + local(本地)收集用到的宏到 aclocal.m4，autoconf 的备料员
autoconfauto + conf(igure)吃 configure.ac，吐 configure 脚本
autoheaderauto + header(头文件)生成 config.h.in，配合 AC_CONFIG_HEADERS 使用（进阶）
automakeauto + make吃 Makefile.am，吐 Makefile.in 模板
libtoolizelib(库) + tool抹平各平台建库(.a/.so)差异，做动态库时才需要
autoreconfauto + re(再) + conf一键全家桶：按序跑 aclocal→autoconf→automake，日常只用它

三、两条日常流程

场景 A：开发者——从零搭项目

# 安装工具链（注意拼写：automake，带 e！）
sudo apt install autoconf automake libtool

# 第一步：扫出 configure.ac 初稿
autoscan
mv configure.scan configure.ac
vim configure.ac            # 手动补宏，见第四节

# 第二步：每个目录写 Makefile.am，见第五节

# 第三步：一键生成 configure（-i 自动补缺失辅助文件）
autoreconf -i

# 第四步：生成 Makefile 并编译
./configure
make
./src/main                 # 跑起来

场景 B：用户——拿到别人的源码包

./configure --prefix=/usr/local   # 指定安装目录
make                              # 编译
sudo make install                 # 安装

四、configure.ac 常用宏

宏名规律：AC_ = AutoConf 前缀，AM_ = AutoMake 前缀

宏作用
AC_INIT([名字], [版本])项目开篇：项目名 + 版本号，必须有
AM_INIT_AUTOMAKE([foreign])启用 automake；foreign = 外来项目模式，免建 NEWS/AUTHORS/README/ChangeLog 四个空文件
AC_PROG_CC找 C 编译器（写 C++ 用 AC_PROG_CXX）
AC_PROG_RANLIB生成静态库(.a)必须加，否则链接报错
AC_PROG_LIBTOOL要用 libtool 做动态库(.so)时加
AC_CONFIG_FILES([...])声明哪些目录要生成 Makefile
AC_CONFIG_HEADERS([config.h])生成 config.h 给代码提供 #define 开关（进阶）
AC_CHECK_HEADERS([unistd.h])检测头文件是否存在（进阶）
AC_OUTPUT收尾：真正输出所有文件，必须有

五、Makefile.am 常用变量

命名铁律：目标名里的 . 和 - 一律换成 _（liblife.a → liblife_a）

变量作用
SUBDIRS = lib src顶层专用：子目录编译顺序。库目录放前面，保证链接前库已存在
bin_PROGRAMS = main要生成的可执行程序（装到 bin/ 目录）
main_SOURCES = main.cmain 的源文件列表
main_CPPFLAGS = -I...预处理参数（头文件搜索路径）
main_LDADD = 路径/liblife.a链接时附加的库（ADD = 添加进来）
main_LDFLAGS = -L... -l...链接器参数
lib_LIBRARIES = liblife.a要生成的静态库
lib_LTLIBRARIES = liblife.lalibtool 库（.la 后缀，可编 .so 动态库）
include_HEADERS = head.h随 make install 一起安装的头文件

六、./configure 选项 与 make 目标

./configure 常用选项

选项含义
--prefix=/usr/local安装根目录（默认 /usr/local）
CC=arm-linux-gnueabihf-gcc指定编译器——嵌入式交叉编译就这么干
CFLAGS="-O2 -g"追加编译选项
--enable-xxx / --disable-xxx项目预设的功能开关

make 常用目标

命令作用
make编译全部
make install安装到 prefix 目录
make clean删 .o 和可执行文件，保留 configure
make distcleanclean + 连 Makefile 也删，回到刚解压状态
make dist打成 项目名-版本.tar.gz 发布包

七、实战样例：liblife 项目（本机可直接抄）

目录结构：autotools/ ├─ configure.ac ├─ Makefile.am ├─ include/head.h ├─ lib/haircut.c, havemeal.c, Makefile.am └─ src/main.c, Makefile.am

configure.ac

AC_INIT([life], [1.0])
AM_INIT_AUTOMAKE([foreign])
AC_PROG_CC
AC_PROG_RANLIB
AC_CONFIG_FILES([Makefile lib/Makefile src/Makefile])
AC_OUTPUT

顶层 Makefile.am

SUBDIRS = lib src

lib/Makefile.am（做静态库）

lib_LIBRARIES = liblife.a
liblife_a_SOURCES = haircut.c havemeal.c
liblife_a_CPPFLAGS = -I../include

src/Makefile.am（做可执行文件）

bin_PROGRAMS = main
main_SOURCES = main.c
main_CPPFLAGS = -I$(srcdir)/../include
main_LDADD = $(top_srcdir)/lib/liblife.a

include/head.h

#ifndef __HEAD_H__
#define __HEAD_H__

void haircut(void);
void havemeal(void);

#endif

八、常见报错对照表

报错原因与解法
bash: ./configure: No such file or directory项目缺 configure.ac，或没跑 autoreconf -i。configure 是生成物，不是 apt 装出来的
E: Unable to locate package autmake拼写错误：应为 automake（掉字母是老毛病了）
required file './install-sh' not found缺辅助脚本。跑 autoreconf -i 或 automake --add-missing
ERROR: required files ... NEWS/AUTHORS/README/ChangeLog没用 foreign 模式。在 configure.ac 加 AM_INIT_AUTOMAKE([foreign])
undefined reference to 'haircut'链接不到库：检查 main_LDADD 路径、SUBDIRS 里 lib 是否排在 src 前
Permission denied（跑 configure 时）WSL 的 /mnt/d 下执行位丢失：chmod +x configure
ar: command not found 类没装编译全家桶：sudo apt install build-essential

九、嵌入式加分项：交叉编译三件套

# 指定交叉工具链编译，产物在板子上跑
./configure CC=arm-linux-gnueabihf-gcc \
            --host=arm-linux-gnueabihf \
            --prefix=/opt/arm-install
make
make install
# CC      = 用哪个编译器
# --host  = 产物要跑在什么平台上（宿主机目标）
# --prefix= 装到哪（避免污染本机 /usr/local）
坑：--host 和 --build 写反是最常见的交叉编译翻车点。--build 是"在哪编"，--host 是"编出来给谁跑"。
