# 合界 · V0.1

统一控制多品牌家电的智能家居网关（简历项目，跑在 RK356X 上）。

## 一句话定位

不做「兼容一百个品牌」的产品，做**「把品牌差异压扁成一层抽象」**的工程。
所有设备在总线上的样子只有三个函数指针：`on` / `off` / `dump`。

## V0.1 范围（已完成）

- 设备抽象层：`device.h` 定义统一设备模型（id / 类型 / 状态 / 私有数据 / 三个操作）
- 设备注册表：`device.c` 静态数组 + 注册 / 查找 / 遍历
- 第一个驱动：`ir_dummy.c` 模拟红外（NEC 码帧打到日志）
- 命令行交互：`main.c` 支持 `list` / `on <id>` / `off <id>` / `quit`

**硬件耦合点只有 `ir_send()` 一个函数**，换真红外时上层一行不动。

## 编译运行

```bash
gcc -std=c11 -Wall -Wextra -g -o hejie main.c device.c ir_dummy.c
./hejie
```

## 路线图

| 版本 | 目标 | 依赖的技能 |
| :--- | :--- | :--- |
| V0.1 | 命令行闭环（当前） | 结构体 + 函数指针 ✅ |
| V0.2 | 接入 SysV 消息队列，驱动拆成独立进程 | `msg_q` 生产者-消费者 ✅ |
| V0.3 | 真红外发射：38kHz 载波 + NEC 时序 | 定时器 / GPIO（新） |
| V0.4 | LVGL 1024×600 触摸面板当遥控器 | LVGL 板端 ✅ |
| V0.5 | socket 服务，手机浏览器可控制 | 网络编程 ✅ |
| V0.6 | MQTT 接智能灯 + if-then 规则引擎 | 多线程 + 协议解析 |

## 面试怎么讲

1. 痛点：小米 / 华为 / 苹果生态割裂，老家电更进不来
2. 核心设计：统一设备模型 + 注册表 —— 品牌差异全部下沉到驱动
3. 工程取舍：V0.1 不搞动态内存和动态扩容，先跑通闭环
4. 难点预留：NEC 时序的定时器精度（微秒级），到时候展开讲
